## 1. Цель продукта и рамки WIP

Платформа для детей 10+ лет. Ученик собирает схемы из узнаваемых реальных компонентов, видит опасные ошибки подключения, меняет Arduino-код и переносит схему и код на реальную плату. Впоследствии задания встраиваются в бесплатный курс Stepik; платные направления — вездеход, катер, коптер, автоматическая многоуровневая парковка, физические лабораторные работы.

**В WIP-001 нужен не дизайн-концепт, а работающий вертикальный срез:** один урок «Мигающий светодиод» от чистого рабочего поля до проверки схемы и отображения результата. Делать фундамент расширяемым, но не реализовывать сегодня все приборы, физику, контроллеры и курсы.

## 3. UX одного урока

Страница `/lab?lesson=blink` с тремя функциональными зонами на широком экране:

1. **Рабочее поле:** узнаваемая плата Arduino Uno с корректными подписями D0–D13, 5V, GND; макетная плата с отверстиями, раздельными группами электрически связанных отверстий и явно маркированными шинами питания.
2. **Панель компонентов:** светодиод с анодом/катодом, резистор (предустановлен 220 Ом, пользователь может менять значение), соединительные провода. Возможность добавить и удалить компоненты, создать/удалить провод, увидеть, куда он включён. Простое и предсказуемое управление мышью; масштаб/компоновка по необходимости. Если drag-and-drop сложен, реализуй явно понятную альтернативу «выбрать компонент → нажать позицию/контакт», но не фиктивные кнопки.
3. **Задание и код:** краткое объяснение схемы, редактор Arduino C++ с реальным текстом скетча, кнопки «Проверить схему», «Запустить», «Остановить», «Сбросить», «Скачать .ino». Видимые ошибки с конкретными объяснениями, понятными ребёнку.

Рабочий сценарий:
- сначала схема пуста (допустима подсказка, но без автоматического прохождения);
- ученик размещает LED и резистор на макетной плате, соединяет Arduino D9 → резистор → анод LED → катод LED → GND (физический порядок LED/резистора в последовательной цепи может быть и обратным);
- нажимает проверку и видит валидность;
- запускает программу Blink, светодиод визуально мигает с заданными задержками;
- меняет время `delay` и частота мигания меняется соответственно (см. ограничения §5);
- сохраняет схему локально и может скачать `.ino`, который компилируется в Arduino IDE для Arduino Uno при использовании поддерживаемого шаблона.

## 4. Модель схемы — не подменять проверку заранее заготовленным ответом

Обязательно выдели независимый от React слой `circuit/`:
- типизированные `Board`, `Pin`, `Hole`, `Wire`, `Resistor`, `LED`, `Circuit` (или эквиваленты);
- у Arduino логические контакты со стабильными ID: `uno:D9`, `uno:GND`, `uno:5V` и др.;
- контакты/отверстия breadboard объединены в электрические узлы по реальной топологии: пять отверстий одной дорожки на каждой половине; центральный разрыв; шины питания — отдельные узлы, не соединённые автоматически с Arduino, а разделение шин соответствует нарисованной модели;
- провода электрически объединяют узлы; резисторы и LED являются **элементами между узлами**, а не просто линиями; для LED учитывается направленность анод→катод;
- отдельная функция строит граф/netlist и отдельный валидатор устанавливает, существует ли правильная последовательная цепь от выбранного цифрового выхода к GND через LED и ограничивающий резистор;
- значение сопротивления реально влияет на предупреждения, а не просто меняется в интерфейсе;
- никакого захардкоженного `if (wireCount === 3) success` и никаких проверок только по пикселям/положениям.

Минимальные ошибки и подсказки:
1. отсутствует GND;
2. разорвана цепь / не тот ряд макетной платы;
3. LED подключён обратной полярностью;
4. LED подключён без токоограничивающего резистора;
5. слишком малое сопротивление (порог/допущения объяснить);
6. короткое замыкание 5V–GND или несовместимые подключения;
7. код использует другой цифровой пин, чем схема.

**Упрощённая физика в WIP-001:** для типичного красного LED принять ориентировочное прямое падение 2 В и для примера напряжение HIGH 5 В. При наличии резистора в последовательной цепи выводить ориентировочный ток `(5−2)/R` и понятную рекомендацию (например, 220–330 Ом). Это учебная оценка, **не SPICE и не точный расчёт характеристик Arduino**. При отсутствии резистора не показывать «бесконечный реальный ток» и не рисовать достоверное «сгорание» — показать предупреждение о потенциальном повреждении. Проверки должны явно указывать границы модели.

## 5. Редактор кода и честная симуляция

Дефолтный Arduino-скетч должен быть настоящим C++ для Arduino IDE:

```cpp
const int ledPin = 9;

void setup() {
  pinMode(ledPin, OUTPUT);
}

void loop() {
  digitalWrite(ledPin, HIGH);
  delay(1000);
  digitalWrite(ledPin, LOW);
  delay(1000);
}
```

**Важно: не притворяйся, что произвольный Arduino C++ исполняется.** Для WIP-001 разрешён узкий, но РЕАЛЬНО РАБОТАЮЩИЙ «учебный режим Blink»:
- из редактируемого кода извлекаются `ledPin`, HIGH/LOW и значения `delay` в рамках явно документированного поддерживаемого шаблона;
- валидатор отклоняет неподдерживаемый код с честной подсказкой, а не показывает заранее заготовленную анимацию под видом исполнения;
- изменения пина или значений задержек должны менять поведение и/или проверку;
- некорректный/неподдерживаемый синтаксис должен давать сообщение «Этот код пока не поддерживается симулятором», без безусловного успеха;
- скачанный `.ino` содержит **ровно пользовательский текст**, без подмены;
- подготовить интерфейс `CodeExecutionEngine`, который позже позволит подключить реальную AVR-симуляцию/компиляцию (например, avr8js + Arduino CLI после отдельного технического исследования).

В документации и UI прямо пометить: «Сейчас поддерживается упражнение Blink, а не всё Arduino C++». Следующая итерация может реализовать реальную компиляцию и исполнение AVR, **не заявлять эту возможность готовой**.

## 8. Тесты и приёмка (обязательно)

**Unit-тесты модели соединений:**
- пять отверстий одной линии в одной половине breadboard соединены;
- половины через центральный канал НЕ соединены;
- две разные линии НЕ соединены;
- шина питания НЕ подключена автоматически к UNO;
- корректная цепь D9 → резистор 220 Ом → LED (анод→катод) → GND определяется;
- обратная полярность LED отклоняется;
- отсутствие резистора обнаруживается;
- короткое замыкание 5V/GND обнаруживается;
- разрыв провода отклоняется;
- другой пин в коде отклоняется;
- 220 Ом даёт ориентировочный ток около 13,6 мА при указанных модельных допущениях.

**Тесты интерфейса:**
- добавить и удалить провод;
- выбрать номинал сопротивления;
- проверить цепь и прочитать ошибку;
- изменить задержку в C++ шаблоне и убедиться, что виртуальное мигание меняется;
- отредактировать неподдерживаемый код и убедиться, что симулятор честно отклоняет его;
- сохранить и восстановить состояние;
- скачать `.ino` с текущим пользовательским кодом.

**Приёмка вручную:** открыть браузер на Windows; собрать цепь с нуля мышью; исправить ошибочное подключение; получить «успех» только после верной сборки; запустить мигание; поменять задержку; обновить страницу и восстановить данные; скачать .ino; убедиться в отсутствии ошибок в консоли.

Дополнительно: npm-скрипты работают; TypeScript проверяется; `npm run build` успешен; тесты действительно запускались; подготовлен адаптивный вид, без горизонтальной прокрутки текста. Визуальные компоненты различимы по контактам и полярности, а не только по цветам.

## 9. Что запрещено и что откладываем

**Не делать в этом WIP:** регистрацию, базу пользователей, магазин, платёжные интеграции, авторизацию Stepik, конструктор любых плат, произвольный Arduino C++ с серверной компиляцией, код для Linux-сервера, полноценный SPICE, физическое повреждение электроники, Web Serial-прошивку, катер/дрон/машинку/парковку.

Не копировать графику Wokwi/Tinkercad или готовые схемы без проверки лицензий. Не тянуть сторонние CDN в продуктивный код. Не реализовывать молчаливо «макетный» интерфейс, где клики ничего не меняют. При технических проблемах приоритизировать работоспособный минимальный пользовательский сценарий над украшениями.
